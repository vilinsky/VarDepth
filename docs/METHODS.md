# Methods for the compact HG005 analysis


### Public data and input construction

The study reused public Illumina HG005 NovaSeq PCR-free WGS and IDT WES alignments on GRCh38. WGS was the public nominal 30× dataset; low-coverage WGS was generated by deterministic one-in-thirty downsampling with seed 41017. The WES input was an independent nominal 100× library. The combined input merged that same WES library with the same downsampled genome library while retaining distinct library identities. Download addresses and the capture BED source are listed in Supplementary Methods. No new participants or specimens were collected.

Input coverage was measured across the autosomes with mapping quality at least 20, excluded SAM flags 1796 and mate-overlap correction, without a base-quality filter. Capture and outside-target summaries used the registered capture intervals and their 100-bp flanks. Physical input depth is distinct from the variant-derived depth context used by the acceptance model.

### Inference architecture and frozen source

VarDepth 0.41.0-rc1 processes aligned reads, a matching reference FASTA, a phased external reference panel and a genetic map. The target sample and its parents are excluded from the panel. Read likelihoods and a copying model over external haplotypes produce local genotype and haplotype context. The implementation selects a bounded set of compatible reference states, uses local read likelihoods and evaluates candidate alleles in fixed windows. Imputation-informed proposals select local candidates; final likelihood evaluation retains the original external prior rather than multiplying that prior repeatedly. This is local haplotype-context inference, not impute-first whole-genome remapping or a graph-reference alignment method.

The frozen workflow uses 4-Mb scientific windows with 200-kb padding and learned downstream correction components. Its coverage guard selects correction only in windows with at least 100 eligible depth observations and median depth between 15.5 and 62; other windows retain native inference. The selected phasing stage preserves genotype evidence and does not connect independent 4-Mb phase sets across their boundaries. The present evaluation measures genotype calling and filtering; preservation of phase fields during filtering is a technical invariant, not an assessment of cis/trans correctness.

### Coverage adaptive acceptance model

The frozen v44 model reuses the v43 histogram gradient-boosted trees, with separate SNV and indel classifiers. Tree training used HG005 chromosomes 1–12; probability calibration used chromosomes 13–14; threshold development used chromosomes 15–16. Parameters were 120 iterations, learning rate 0.08, at most 15 leaves and depth 4, a minimum of 80 samples per leaf, L2 regularisation 5, 127 histogram bins, no early stopping and random seed 43017. The 29-feature schema and complete model are supplied with the source.

Depth grouping uses the maximum of FORMAT/DP and FORMAT/ADP, with edges 0, 1, 4, 10, 30 and 100; the uppermost group includes depths at least 100. Local context uses median VCF SNV depth in 50-kb windows with at least 20 eligible anchors. Isotonic mappings and depth-specific thresholds are frozen in model44.json. They were developed using genomic F1 and baseline safeguards in the tuning regions, with final candidate assessment by hap.py. No model fitting or threshold modification occurred in the present compact analysis. Earlier development and outcome inspection mean that the nominal chromosome split is not an independent validation of the complete pipeline.

The model operates on eligible calls while preserving hard filters. Unmodelled records marked only LowQual inherit the preceding sensitivity policy rather than being rejected solely for lacking a score. A zero acceptance threshold bypasses unnecessary scoring, recording a missing score instead of an artificial probability. The filter changes FILTER and adds its own provenance fields; digest checks require all original alleles, genotypes, quality and phase information to remain unchanged. The model SHA-256 is cd5d44ebdc52ac2aee97bb08113529267dbbb40a3ecc2d6c413873a083c4602b.

### Comparator configurations

GATK 4.7.0.0 was run as HaplotypeCaller in GVCF mode followed by GenotypeGVCFs, with eight native PairHMM threads and without a separate VQSR or hard-filtering stage. DeepVariant 1.10.0 used its WGS model for WGS and low-coverage WGS, and its WES model for WES and the combined input, with eight shards. This tests the selected released models at their respective input depths, including a low-coverage regime outside the usual high-depth calling use case.

GLIMPSE2 2.0.0, commit 88915f7, used its BAM-based mode and precomputed reference chunks with seed 17. QUILT2 2.0.4 used diploid mode, seed 17, nGen 100 and a 500-kb buffer. Prepared references derive from the registered shared panel with the target and parents excluded; QUILT2's evaluated reference representation is SNP-only. GLIMPSE2 chunks were ligated with its native ligation utility, and QUILT2 outputs were joined with registered core ownership and phase checks. Missing QUILT2 WGS assessments on chromosomes 18 and 20 and QUILT2 indels remain unavailable. The comparison concerns these versions and configurations, not all possible caller or imputation pipelines.

### Benchmark regions and metrics

PASS calls were assessed against GIAB v4.2.1 HG005 GRCh38 confident regions using the existing hap.py/vcfeval evaluations, following representation-aware benchmarking principles [6,7]. SNVs and 1–50-bp indels were analysed separately. The primary matched scope was chromosomes 18 and 20 in all four input configurations, chosen for completed comparable assessments. It contained 165,860 truth SNVs and 20,104 truth indels. Contexts were all confident regions, confident regions within WES targets and confident regions outside targets plus 100-bp flanks.

The separate descriptive target analysis included all 22 completed autosomes for low-coverage WGS, WES and combined input. WGS used the same 12 completed chromosomes for every method: 1, 2, 3, 4, 6, 8, 10, 12, 14, 16, 18 and 20. This scope does not constitute a completed all-autosome WGS benchmark. The target truth denominators were 25,106 SNVs and 925 indels for the 22-autosome scope, and 14,808 SNVs and 554 indels for WGS.

Query true positives, truth true positives, false positives and false negatives were summed before calculating precision, recall and F1. Precision equals query TP divided by query TP plus FP; recall equals truth TP divided by truth TP plus FN; F1 is their harmonic mean. Query and truth TP were kept separate because representation-aware matching can yield unequal counts. All 534 method–input–chromosome count tensors were checked against 41,118 metadata rows, and 153 previous primary aggregate rows were reproduced exactly.

### Paired regional resampling

We used 10,000 paired bootstrap repetitions with fixed 2-Mb blocks resampled within each chromosome; 1-Mb and 4-Mb blocks were sensitivity analyses. Blocks were constructed from the existing 1-Mb count tensors. The random seed was 20260929 plus the block width in megabases, with the same chromosome-specific block multiplicities applied to every method and input. Each repetition summed counts before recalculating the metrics and their paired differences. Intervals are the 2.5th and 97.5th percentiles.

These pointwise regional intervals condition on this sample and the evaluated regions. They do not account for between-person variation, prior development exposure, all long-range dependence or multiple comparisons. Six sparse low-coverage target-indel method-by-block-width cells had undefined F1 in 0.46–4.77% of repetitions because no query calls were sampled. Their intervals use finite pairs only and are not used for superiority claims. Every highlighted primary contrast retained all 10,000 pairs. No significance tests or multiplicity-adjusted population claims were made.

### Implementation timing and integrity

Timing used chromosome 20 on an Intel Xeon Icelake CPU with Python 3.12.3 and pysam 0.22.0, pinned to one CPU under a one-core quota. Each input had one warmup per backend followed by three interleaved measured pairs. The timed function included depth profiling, feature extraction, inference, VCF I/O, indexing and internal hashing. Imports, native library loading and an additional subsequent per-record comparison were excluded from the wall-time measurement. Per-process peak RSS, measured over the broader process lifetime, was approximately 60–65 MiB. All individual measurements and output hashes are in Supplementary Data 2.

### Use of generative AI tools

OpenAI Codex assisted software implementation, analysis scripting, literature retrieval, drafting and document preparation. The computational tasks were to preserve the frozen model, aggregate existing benchmark counts, perform paired regional resampling and verify exact-output timing comparisons. Figures were plotted deterministically from measured aggregate data with Matplotlib; no generative image model was used. Source code and numerical outputs are retained for inspection. Author verification and responsibility for the final submission remain essential.

### Data availability

Public sequence and truth-data locations are provided in Supplementary Methods. Aggregate block counts, complete metrics, resampling results and timing records accompany this article and the VarDepth repository. Per-site callsets and training matrices are not redistributed in this package. The supplied block-count replay reproduces aggregate analyses; a new end-to-end caller run additionally requires the registered sequence, reference, panel and map inputs.

### Code availability

Source code, frozen model weights, the original locked Linux caller artifact and aggregate analysis scripts are available at https://github.com/vilinsky/VarDepth. The model and source checksums identify the evaluated implementations. The public snapshot is inspectable; an additional open-source reuse licence has not yet been selected.
